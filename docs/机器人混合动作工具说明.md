# 机器人混合动作工具说明

适用于 Hermes 经 MCP 调用 Blender 的固定 Beta 机器人流程。以下名称已存在于 `scripts/preload_helpers.py`，通过 `bpy.wm_agent_*` 调用。`JOB` 必须替换为当前任务已有的真实 `job_id`；示例按需要选用，不是一条连续演示脚本。不同 MCP 调用的 Python 局部变量可能不保留，应从场景或接口重新读取。

用户只输入自然语言。Hermes 保留原文中的人物、动作、先后、左右侧、物品、接触结果、时长和镜头要求，再选择库动作、同骨架新动作或两者混合。素材 ID、骨骼名和事件 JSON 是内部实现参数，不应要求用户改用它们描述动作。

## 1 固定人物与动作检索

```python
import bpy
JOB = "当前任务的真实job_id"

print(bpy.wm_agent_character_info("beta"))
print(bpy.wm_agent_actor_ensure(JOB, "A", position=(0, 0, 0), yaw=0))
print(bpy.wm_agent_actor_info(JOB, "A"))

result = bpy.wm_agent_motion_search("先走路，再跑向窗户", limit=8)
print([{"id": c["motion_id"], "name": c["name"], "reason": c["match_reasons"]}
       for c in result["candidates"]])
print(bpy.wm_agent_motion_info("mixamo.basic.walk"))
```

人数由 Hermes 理解原文后决定。新增 B、C 时分别调用 `wm_agent_actor_ensure`，使用不同 `actor_id`。同一个 ID 重复调用会复用原人物，保留其位置与动画；需要移动已存在的人物时应修改其根轨迹，而不是依靠重复 `ensure` 改位置。

修复时用 `wm_agent_actor_list(JOB)` 查看实际登记、对象和缺失情况。错误重复人物用 `wm_agent_actor_remove(JOB, 错误actor_id)` 清理；先确认正确人物，删除后再次查询和检查画面。工具按实际所有权删除指定人物的根、骨架、蒙皮和控制器，并清理对应登记/时间线；其他人物与物品保留。不能只把重复人物隐藏或移到画外，也不能删除局部网格而留下失效登记。

目前目录有 63 个本地 FBX 和 3 个已登记 Quaternius GLB 片段。检索返回选材候选，不判定完整提示词是否可以执行。没有合适候选时，在当前机器人的骨架上继续构建；不能把“翻窗”改成素材里的“跳跃”，也不能删掉没有素材的招手或受击后退。

原 Beta 骨架约为0.01缩放，骨通道仍使用源骨空间坐标。局部骨轴不等于世界轴，局部Y通常沿骨长；直接设置identity会回rest姿态。新动作保留真实库底层，并用实际世界目标、当前父骨/rest矩阵或 `Object.convert_space` 做坐标转换。触摸测实际蒙皮接触，深蹲测世界髋高下降、屈膝与足支撑，转身测 `Root.matrix_world` 朝向。工具返回成功和动作名称不能替代这些测量。

从IK求值姿态生成FK事件时，`agent_motion_controls.read_pose(armature, evaluated=True)` 已反算parent/rest矩阵，可取得真实局部骨通道；直接用parent逆矩阵乘pose矩阵的quaternion仍含rest旋转，会导致二次旋转。人体右轴依据底层姿态中世界 `RightArm.head - LeftArm.head`，前轴由人体上轴与右轴叉乘取得；不要将机位的世界+X当成本人右侧。食指方向与收回需检查实际Index骨和皮肤。

## 2 库动作段与统一时间线

先登记各动作段，再统一 `commit`，避免每登记一个事件都重复烘焙全片。

```python
import bpy
JOB = "当前任务的真实job_id"

# 以下 150 帧、30 FPS 是这个示例的时长；实际任务按原文设置。
scene = bpy.context.scene
scene.frame_start, scene.frame_end = 1, 150
scene.render.fps, scene.render.fps_base = 30, 1

bpy.wm_agent_timeline_event(JOB, "A", "walk_approach", {
    "source": "library", "intent": "先走路",
    "motion_id": "mixamo.basic.walk",
    "start_frame": 1, "end_frame": 90,
    "loop": True, "fit": False,
    "root_mode": "extract_planar", "root_strategy": "source",
})
bpy.wm_agent_timeline_event(JOB, "A", "run_approach", {
    "source": "library", "intent": "接着跑步",
    "motion_id": "mixamo.basic.run",
    "start_frame": 91, "end_frame": 150,
    "loop": True, "fit": False,
    "blend_in_frames": 8,
    "root_mode": "extract_planar", "root_strategy": "source",
})
print(bpy.wm_agent_motion_commit(JOB, "A", frame_start=1, frame_end=150))
```

帧区间包含两端。输出帧数为 `end_frame - start_frame + 1`；事件时序与场景真实 `fps / fps_base` 对应。`loop=True` 是调用者明确选择循环，工具不会因为片段短就自动重复拳击、倒地等一次性动作。`fit` 默认会将非循环片段映射到事件时长；保持素材速度可设置 `fit=False`，或明确指定 `time_scale`。

`source_window=[开始秒,结束秒]` 裁剪的是源片段时间，秒数相对于源 Action 第一帧，不是场景帧号。目录中的 `phases`、`source_peak`、`source_window_frames` 是源帧标注，需要按实际源帧率及起始帧换算。导入后的实际时长可由 Python 的 `agent_motion.prepare_motion(armature, motion_id)` 查询。不要把动作阶段均分或只保留攻击峰值，丢掉蓄力、恢复和合理结束姿态。

`root_mode="extract_planar"` 将源水平位移与骨盆残余动作分开；`root_strategy="source"` 使用该位移，并按本段开始时继承的根姿态进行朝向与缩放转换。例如先转 90 度再走路，后一段应沿转身后的方向移动。`root_path` 使用根节点父空间的米坐标，通常是世界空间，可配合 `root_strategy="trajectory"` 控制路线。`hold` 保持根节点位置。`root_mode="preserve"` 会把源水平运动留在骨盆里，额外再加同一根位移会造成重复移动。

`wm_agent_motion_apply(JOB, actor_id, segment)` 是登记库段并立即烘焙的便捷接口；批量编排优先使用上述登记、统一提交方式。段包含程序关键帧或目标时，可使用 `source="hybrid"` 并保留 `motion_id`。

### 平地步态、刹步与站稳

`wm_agent_locomotion_apply(JOB, actor_id, path, event_id="locomotion_base", intent="原文动作意图")` 在现有原始 Beta 上结合 Idle/Walk/Run 素材与双足 IK，覆盖完整连续轨迹，不创建新身体。`path` 为逐帧连续整数帧列表，每项为 `{"frame":帧号,"root":[世界米x,y,0],"yaw":弧度,"gait":"walk"}`，gait 可为 walk/run/idle。Hermes 从自然语言计算时间、路线、速度和朝向，用户无需输入这些字段。

走跑共用一个相位时钟。减速时实际根速度连续降低，移动中的刹车阶段仍使用 walk/run；速度归零后 idle 继续收脚落足，必须留足站稳时间。根位置还在移动却使用 idle 会得到明确错误，避免把滑动当作停止。工具仅针对世界 Z=0 平地、竖直无父级且单位缩放的根节点校准；原 FBX 骨架约 0.01 的缩放保持。其他坡面、楼梯或腾空动作仍可自由构建，这些限制只属于可选工具。

结果为同一骨架上的完整持久关键帧，保全窗口外的实际最终运动，不重新叠加旧 FK/IK。使用稳定 event_id 修复同一段。返回真实素材窗口/hash、实际烘焙范围及末帧脚底高度；完整轨迹和逐帧足支撑记录可按需从 `wm_agent_timeline_info(..., detail=True)` 取得。`naturalness_verified=False` 明确表示仍需看实际画面，不能把工具成功当成成片自然度认证。真实隔离骨架测试见[步态记录](../reports/agent_locomotion_validation_20261014.json)。

该步态最终姿态的默认 priority 比已有事件高。后续“边走边挥手”等局部层需先查询该事件真实 priority，再设置更高值；默认 priority=0 的旧层会被完整最终姿态保全层覆盖，不能当作同时动作已执行。

## 3 缺失动作使用当前骨架的 FK 或 IK

获取现有人物的骨架和姿态，再写需要变化的通道。保留未修改的身体运动。骨骼本地位移使用该骨架原单位，Beta 骨架保留约 `0.01` 的导入缩放；人物根位置、物品锚点与 IK 世界目标使用米。四元数顺序为 `[w,x,y,z]`。

```python
import bpy
from agent_character import resolve_actor
from agent_motion_controls import read_pose
from mathutils import Quaternion
JOB = "当前任务的真实job_id"

actor = resolve_actor(JOB, "A")
bpy.context.scene.frame_set(121)
pose = read_pose(actor["armature"], evaluated=True)
bone = "mixamorig:RightHand"
q0 = Quaternion(pose[bone]["rotation_quaternion"])
q1 = q0 @ Quaternion((1, 0, 0), 0.35)

# 示例仅演示腕部 FK 叠加，不把它当作已完成自然招手。
bpy.wm_agent_timeline_event(JOB, "A", "right_wrist_change", {
    "source": "procedural", "intent": "右腕局部变化",
    "start_frame": 121, "end_frame": 150,
    "mask": [bone], "blend_in_frames": 5, "blend_out_frames": 5,
    "keyframes": [
        {"frame": 121, "pose": {bone: {"rotation_quaternion": list(q0)}}},
        {"frame": 135, "pose": {bone: {"rotation_quaternion": list(q1)}}},
        {"frame": 150, "pose": {bone: {"rotation_quaternion": list(q0)}}},
    ],
})
```

`mask` 可使用实际骨名，也支持 `right_arm`、`left_arm`、`upper_body`、`lower_body`。这些是控制区域，不是用户动作白名单。局部事件不应拥有全局根运动。没有 `mask` 的事件负责基础姿态；时间空档保持前一段结束姿态。不要先把全部骨骼四元数清为单位值再拼四肢，也不要插入 rest/T 姿态填空。

需要撑扶、触摸、落脚或命中时，在同一骨架上使用现有双骨 IK。公开接口为 `wm_agent_actor_controls(JOB,"A")` 和 `wm_agent_controls_match(JOB,"A",chain="RightHand")`；可用链为 `LeftHand`、`RightHand`、`LeftFoot`、`RightFoot`。先匹配当前 FK 末端和肘膝方向，再逐渐启用目标影响。

事件的 IK 格式如下；`p_start`、`p_contact` 应从当前求值手部和物品真实锚点读取，不使用对象中心代替接触面。

```python
event = {
    "source": "procedural", "intent": "右手接近并接触目标",
    "start_frame": contact_start, "end_frame": contact_end,
    "mask": "right_arm",
    "targets": {"RightHand": {"keyframes": [
        {"frame": contact_start, "position": list(p_start), "influence": 0},
        {"frame": contact_frame, "position": list(p_contact), "influence": 1},
        {"frame": contact_end, "position": list(p_contact), "influence": 0},
    ]}},
}
bpy.wm_agent_timeline_event(JOB, "A", "right_hand_contact", event)
```

可在目标关键帧补充世界空间 `pole` 和 `rotation_quaternion`。目标在运动中需要保持与实际路线、物品或对方身体一致。够不到时调整允许的接近路线、躯干姿态或运动阶段；工具禁用拉伸，并在烘焙结果 `unreachable_targets` 中记录不可达目标。IK 本身不自动生成重心、脚步支撑、打击力度或被打者反应，这些要分别编排和验证。

搬运或手持物品可以由物品轨迹驱动手部 IK，或由手驱动物品随动。前者让双手从物品同帧握点求解；后者使用骨骼 parent 或 `CHILD_OF` 等约束。骨骼 parent 应保存世界矩阵，将 parent 设为真实 armature、`parent_type='BONE'`、`parent_bone=实际手骨名`，更新求值后恢复世界矩阵；松手保持当帧世界矩阵。PoseBone 世界矩阵为 `armature.matrix_world @ hand.matrix`。IK 先求值再烘焙实际结果，正确烘焙后可静音约束。检查真实末端与握点在接触窗口内的距离及释放、保存重载结果，约 0.03 米可作为容差起点；物品和手不能只是互不关联的轨迹。

Hermes 也可以直接通过 `bpy` 在原骨架上创建更复杂的关键帧、约束和控制器。结束后使用 `wm_agent_motion_commit(..., capture=True)` 捕获真实求值运动，不能仅保存 Python handler 或内存采样缓存。

### 移动接触目标与相关人物协调

目标可以绑定到实际物体、对手骨骼或求值后的网格顶点。下面只演示接口；`target_skin_name`、`target_vertex_index`、`striker_skin_name`、`fist_vertex_index` 必须由真实人物网格选取，不把手腕或头骨中心当成拳面或皮肤表面。

```python
# 已在 A、B 上登记各自的基础运动；沿用实际 actor_id。
bpy.wm_agent_timeline_event(JOB, "A", "punch_contact", {
    "source": "procedural", "intent": "拳面在指定窗口接触对手身体后收回",
    "start_frame": 1, "end_frame": 30, "mask": "right_arm",
    "targets": {"RightHand": {
        "binding": {"object": target_skin_name, "vertex_index": target_vertex_index},
        "effector": {"object": striker_skin_name, "vertex_index": fist_vertex_index},
        "keyframes": [
            {"frame": 1, "influence": 0}, {"frame": 13, "influence": 0},
            {"frame": 15, "influence": 1}, {"frame": 17, "influence": 1},
            {"frame": 23, "influence": 0},
        ],
        "contact": {"start_frame": 15, "end_frame": 17,
                    "tolerance_m": 0.03, "kind": "strike"},
    }},
})
print(bpy.wm_agent_motion_commit(JOB, ["A", "B"]))
print(bpy.wm_agent_motion_check(JOB, check_camera=False))
```

其他绑定形状为 `{"object": 实际物体名, "local_point": [x,y,z]}` 或 `{"actor_id": "B", "bone": "Head", "local_point": [x,y,z]}`。骨骼短名必须唯一。局部点使用实际对象或骨骼局部单位，通过真实求值矩阵转为世界米；Beta 骨骼的局部数值不能直接按世界米解释。`vertex_index` 始终针对实际求值网格；拓扑改变或目标丢失应重新选点并检查。

`effector_point` 可描述末端骨的局部点，默认零只代表骨起点；真实拳面、掌面优先使用自身蒙皮顶点。绑定默认派生整段事件的接触要求，实际只在命中或持有期间接触时必须用 `contact.start_frame/end_frame` 限定窗口；护架等仅跟随身体的目标设 `contact=False`。瞬时击打之后降下 IK 权重，恢复基础姿态中的收招，不让拳头持续追随后退身体。

`pole_binding` 使用同样的绑定格式，使肘/膝方向目标随稳定的链外骨或物体移动；`pole_angle` 单位为弧度。护架和出拳工具复用链外肩部目标及校准角，拳朝向在准备、命中、收招之间连续变化，实际腕目标可达性包含拳部表面偏移。

列表形式的 `motion_commit` 先计算相关人物基础运动，再逐帧恢复基础姿态、按该帧依赖求同帧 IK，最后统一烘焙；有事件的目标人物会一并协调。先 A 打 B、随后 B 反击可交换驱动顺序；真正同帧循环在修改动画前指出错误帧。返回 `dynamic_commit_order` 和压缩的 `dependency_windows`。直接 bpy 修改仍先逐人 `capture=True`，再重新登记或调整相关事件；列表提交不同时执行 capture。

`motion_check` 默认复查登记的接触窗口。场景保存会记录接触契约，后台独立重载后复核完整窗口和要求是否变化。查看实际误差、失败帧与作用范围；没有登记接触只表示空契约，原文明确接触要求仍须对应执行事件和检查。该机制不认证受击动力学或动作自然度。

## 4 修复一个事件与接入已有 recipe

相同 `event_id` 会替换该事件，保留其他事件。替换时提交完整事件字典，然后再次统一烘焙。直接改过 Action、NLA 或驱动而未登记时，追加事件或普通 `commit` 都会返回错误并保留现有动画；应使用 `capture=True` 捕获实际运动，再继续编排。

```python
import bpy
JOB = "当前任务的真实job_id"
store = bpy.wm_agent_timeline_info(JOB, "A", detail=True)
event = next(e for e in store["events"] if e["event_id"] == "run_approach").copy()
event["blend_in_frames"] = 10
bpy.wm_agent_timeline_event(JOB, "A", "run_approach", event)
print(bpy.wm_agent_motion_commit(JOB, "A"))
```

`wm_agent_build` 构建完整 recipe 场景，`wm_agent_load` 会打开该场景，不能当作给当前人物追加单段动作的接口。确实选择 recipe 时，用当前任务构建，等 `wm_agent_build_status` 完成，再加载；检查实际骨架和网格后按以下顺序接入：

```python
import bpy
JOB = "当前任务的真实job_id"
print([(o.name, o.parent.name if o.parent else None)
       for o in bpy.context.scene.objects if o.type == "ARMATURE"])

# 用上一项检查得到的真实骨架名，必要时传 root_name=真实父对象名。
print(bpy.wm_agent_actor_adopt(JOB, "A", actual_armature_name))
print(bpy.wm_agent_motion_commit(
    JOB, "A", capture=True, event_id="existing_recipe",
    frame_start=bpy.context.scene.frame_start,
    frame_end=bpy.context.scene.frame_end,
))
```

此后登记新事件、扩展场景 `frame_end`，再次 `commit`。多人 recipe 分别登记、捕获每个人。`adopt` 检查原 Beta 骨架、网格、权重和绑定关系，不重造人物。用直接 FK/IK 编辑已有 recipe 后再次捕获时，保持稳定事件 ID，并明确捕获区间。

已验证原翻窗 300 帧及双人拳击 90 帧可以采用此流程，追加右臂区域 FK 后，原全部骨骼与蒙皮顶点误差不超过约 `2.6e-6 m`，新场景重载误差为零。该验收证明同人物接入和持久化，不证明追加段已经自然招手，见[适配验收记录](../reports/robot_recipe_adapters_20261014.json)。

默认查询返回紧凑摘要，省略每帧姿态、目标和根路径。修复事件时使用 `detail=True` 取得完整字典，避免把摘要覆盖回事件而丢失关键帧。

局部 `capture=True, frame_start=..., frame_end=...` 只采集该窗口的实际改动，完整烘焙仍覆盖既有时间线；不会为了保存最后一段而清掉前面的动作。返回 `requested_range`、`captured_range` 与 `actual_bake_range`，`frame_start/end` 表示最终实际烘焙范围。同一捕获事件缩短窗口时，范围外原运动会保留。轨迹使用 `root_path` 的 `root` 米坐标，源窗口使用 `source_window` 秒；`root_trajectory`、`source_window_frames` 等错误执行字段会得到明确诊断，不能当作已生效。

捕获的姿态已经包含窗口中原有的 FK/IK 层，不应在重放时再次叠加这些低优先级层。自行生成的完整最终全骨姿态也可在事件中标记 `final_pose_layers=True`；该标记只适用于真正完整的关键帧。更高优先级的新局部层仍可追加，窗口外保持既有结果。检查保存重载及实际蒙皮，不能仅凭字段宣称姿态保全。

捕获保全层优先级高于旧层。随后用新 base 或局部 overlay 修改同一窗口时，先查询实际 priority，再让需要接管的新事件高于它。默认 priority=0 的新层可能被原捕获结果覆盖；登记成功不证明改变了实际姿态。

局部捕获的窗口外会保存原实际完整姿态，避免旧自动 IK pole 重算导致未改区域漂移。之后明确编辑这些自动保全窗口时，未指定 priority 的新事件自动取得更高优先级；显式 priority 保持原值。登记返回 `priority_diagnostic`，包含 `effective_priority` 和 `shadowed_by_preserved_base`。被保全层覆盖的低优先级记录应调整后再烘焙；新的局部层只接管所选骨区，完整保全基底继续保持其余部位。

## 5 核对、保存与能力边界

先完成动作并烘焙，再按原文构建镜头。要求固定全景时可使用参考相机适配器；移动、近景与其他镜头仍可直接 `bpy` 实现。世界正前方是 `-Y`，右方是 `+X`；世界方位 `60` 配机位仰角 `+20` 表示从右前上方观察并俯看，不是以 `+Y` 为前方计算。

```python
import bpy
JOB = "当前任务的真实job_id"
full = bpy.wm_agent_camera_full(JOB, {
    "reference": "world", "azimuth_deg": 60, "elevation_deg": 20,
    "projection": "orthographic", "fov_deg": 50,
    "occlusion_policy": "strict",
})
print(full)
```

可传 `actor_ids=["A","B"]` 选取已登记人物，`focus_objects=[真实桌子或窗口MESH对象名]` 将实际物品也纳入构图。工具读取完整时段的求值原蒙皮，不改人物与动画，返回真实 `camera` 名及 requested/applied `facts`。再次设置全景时，仅更新工具管理的全景/返回 marker；其他用户镜头保留。这个内部适配器支持固定全身构图；特写、移动镜头等其他需求仍可由 Hermes 直接 `bpy` 构建，不能把组件支持范围当成提示词限制。

### 登记镜头需求并检查真实可见性

`wm_agent_camera_check` 以实际场景求值几何检查用户要求看见的目标。传入 `requirements` 会先持久化登记到场景；省略后复查既有登记，缺登记返回 `status="missing"`。`ok` 表示调用执行，`passed` 和 `scope` 表示指定范围的检查结果，不能只看 `ok=True`。新提交保存 `camera_visibility_version=1`，后台重载再检查全片；失败会先交回 Hermes 修复再重提交，停止该失败版本出片。

每个镜头窗口至少登记一个实际人物或关注物品；含人物时可见区域不能为空。全身镜头默认检查头、躯干和双脚，局部镜头按原文登记相应区域。仅物品镜头可以不登记人物区域。这些要求用于保证检查确实覆盖画面主体，不限制用户提示词中的人数、动作或场景。

`camera_full` 的拟合阶段最多检查包含首尾的 12 个代表帧，返回 `visibility.helper_sample_frames`、`helper_sample_scope` 与 `backend_full_frame_visibility_required=True`。该结果只覆盖这些帧，完整镜头需求仍登记整个窗口。`camera_check` 默认检查全片；长视频可指定 `frame_start`/`frame_end` 分段检查并说明实际范围，正式提交后的独立后台仍验证所有帧。不要把代表帧拟合或某个局部段通过当成整片认证。

```python
import bpy
JOB = "当前任务的真实job_id"
scene = bpy.context.scene

# 此例只登记单个全景；相机与物品名字须从真实场景取得。
requirements = {"version": 1, "shots": [{
    "camera": "真实全景相机名",
    "frame_start": scene.frame_start, "frame_end": scene.frame_end,
    "actor_ids": ["A"],
    "focus_groups": {
        "chair": ["真实椅背MESH", "真实座面MESH", "真实四腿MESH"],
        "door": ["真实门MESH"],
    },
    "framing": "full_body", "margin": 0.04,
    "fixed_transform": True,
}]}
print(bpy.wm_agent_camera_check(JOB, requirements=requirements))
# 修改相机或运动后复查；detail=True按需取得逐帧记录。
print(bpy.wm_agent_camera_check(JOB))
```

`camera` 是实际相机对象名，帧区间包含两端。`actor_ids` 使用真实登记人物 ID；`focus_groups` 按逻辑物品列出全部实际 MESH 部件，不填仅作父级的 Empty 名。要求整把椅子、门和落地位置可见时，椅背、座面、四腿及门几何不能从检查里省略。部件可以是多个 MESH，也可以是一个包含这些部件的整体 MESH。每组全几何必须入框，允许椅座自然遮住远侧椅腿等组内正常互挡；外墙或其他人物挡住整组仍接受遮挡检查。旧 `focus_objects=["实际MESH名"]` 继续支持单独物件。固定全景 helper 的 `focus_objects` 还可传 `{"id":"chair","objects":["实际椅背", "实际椅座", "实际椅腿"]}`，由 helper 登记对应逻辑组；单独字符串用法兼容。

全景使用 `framing="full_body"`。近景与 POV 使用 `framing="regions"` 并指定 `regions`，可选 `head`、`trunk`、`left_arm`、`right_arm`、`left_hand`、`right_hand`、`left_foot`、`right_foot`；臂含上臂和前臂，手单列，足含脚趾。多个约束可以在同一镜头窗口分别要求本人出拳手、对方头/躯干等目标。存在分镜时按实际 camera markers 分段登记，不能把全景全身规则套在明确要求的第一视角上。

原文明确镜头数值时，可加 `expected_position` 与 `look_at`（世界米），`expected_azimuth_deg`、`expected_elevation_deg`、`reference_yaw_deg`、`expected_fov_deg`、`expected_projection`；要求固定时加 `fixed_transform=True`。方位和俯仰角字段必须同时提供 `look_at` 世界参考目标，否则登记报错，不能静默跳过角度检查。未明确不强制固定或某个角度；自定义动态镜头也按自己的窗口与可见区域检查。明确的位置、角度、焦距不能为通过检查静默更改。模糊“斜侧、略微俯视”允许 Hermes 合理调整机位、焦距/投影或 look_at 来显示目标。

检查入框与不透明物遮挡后仍需看真实代表帧与过渡。不得为了取景修改已正确的人物和物品轨迹、删动作、缩短时长、隐藏/删除墙体或擅自透明化；用户明确允许剖切/cutaway时才采用。相机失败应保留真实动作，读取失败帧、目标、遮挡物和数值偏差，修镜头后复查。工作流中的人物 pose/root 通道哈希保护只覆盖这些通道与时长；物品和全片几何是否保留另行核对，不宣称它认证完整物理、所有像素可见或自然度。

再按动作事件设置第一视角镜头：

```python
import bpy
JOB = "当前任务的真实job_id"
# B 是出拳者及眼位持有者，A 是被观察者；FullCamera须为场景真实相机名。
print(bpy.wm_agent_camera_pov(
    JOB, "B", "A", start_frame=100, end_frame=130,
    fov=75, return_camera="FullCamera", shot_id="B_counter",
))
```

`fov` 是水平角度。镜头根据 B 求值后的头骨近似眼位跟随，并注视 A 的真实头部/胸部；眼位属于 B，而不是从 A 的位置拍 B。工具绑定时间线 camera markers，在 `end_frame+1` 回到指定或此前的相机。B 原有 Head/Neck 权重组只在这段的渲染中用 MASK 遮头，viewport、碰撞用原网格、顶点与蒙皮不变；不拆出头部或身体副本。眼位是骨骼近似，没有精确眼部解剖保证。

改变任何一方动作后重新调用 `wm_agent_camera_pov` 烘焙该镜头。修复同一镜头时沿用显式 `shot_id`；调整起止时间会替换旧窗口、相机关键帧与本工具的遮头关键帧。不同镜头的窗口包含端点不能重叠：一帧只有一个活动第一视角，相互重叠会使多个人同时遮头，所以工具在任何修改前返回明确冲突。Hermes 应修正分镜时序或直接实现其他镜头形式；这不是动作/提示词白名单。省略 `shot_id` 时保留按人物及起止帧生成 ID 的兼容行为，因此需要移动原窗口时建议明确 ID。

观看真实代表帧，确认自拍者的出拳手臂、对方及反应结果确实可见；数据和 marker 通过仍可能手臂出画。早期头部为主的注视样例出现过这个问题，当前已验证的胸部为主注视样例在固定骨眼位、75 度视野中能看到自己的蓝色拳臂与红色目标。它证明视角工具可用，不替代命中或受击退步质量验证。

```python
import bpy
JOB = "当前任务的真实job_id"
print(bpy.wm_agent_motion_check(JOB))
print(bpy.wm_agent_scene(JOB))
```

### 场景照明与黑帧

EEVEE/Cycles 场景必须实际有照明才能出片。清空场景或自建场景后，如果没有可见灯光、`scene.world` 为空或全黑、也没有自发光材质，渲染结果会全黑。可以调用 `bpy.wm_agent_lighting(JOB)` 为当前场景补齐 `World` 与三点光（`AutoKey/AutoFill/AutoRim`），也可以自行用 `bpy.data.lights` 新建 `AREA`/`SUN` 并设置 `scene.world`。

```python
import bpy
print(bpy.wm_agent_lighting("当前任务的真实job_id"))
```

后台探针会把「完全无照明的 EEVEE/Cycles 场景」判为错误并交回 Hermes 修复；保存时框架也会兜底补默认照明并在 `warnings` 中记录，但应主动打灯以控制画面效果。仅设置 World 名称、创建灯光数据块或看到视口实体，都不证明正式帧有照明；预览代表帧并确认不是黑帧。只要求白模且无明确渲染引擎时，可改用 `BLENDER_WORKBENCH`（`scene.display.shading.light='STUDIO'`），其使用显示光照，不需要场景灯光。

代表帧采用后台快照渲染，避免占住 MCP 主线程：

```python
import bpy
JOB = "当前任务的真实job_id"
preview = bpy.wm_agent_preview(JOB, frames=[1, 60, 90], resolution=[640, 360])
print(preview)
# 后续独立MCP调用重新取得上述真实preview_id；不要长循环等待。
print(bpy.wm_agent_preview_status(JOB, preview["preview_id"]))
```

先保存并烘焙实际运动，再启动预览。快照保留当前引擎、材质、人物、镜头和 FPS；子进程只按明确预览分辨率导出 PNG。返回 `ok=True` 或 `queued/loading/rendering` 只表示任务正在执行；查询 `status=complete`、所需帧数量和每张 `images.available`，才能确认图片已经生成。报告包含快照与图片哈希。动作、材质或镜头修改后重新启动预览，不拿旧快照验证新场景。预览失败记录实际原因，继续真实数据检查及场景提交，后台仍从正式场景出片；不把失败转换成视觉通过。

相机应由 Hermes 按原文设置，并检查变形后的实际人物和相关物品。`wm_agent_camera_check` 是登记镜头窗口、关注物品与可见区域后的独立检查；`wm_agent_motion_check(JOB, check_camera=True, frame_start=段开始帧, frame_end=段结束帧)` 仍可用于所选全景段的原蒙皮投影核对，单凭该项不能证明椅子/门完整或没有遮挡。第一人称或明确要求的近景不应套用全人物入画检查。`motion_check` 的 `passed` 只表示所请求的身份、几何、通道、边界及可选镜头/接触检查通过。接触检查测量指定骨头与目标点或求值表面的距离，不等于掌面贴合、力学或打击感验收。正式保存后沿用后台独立重载、渲染和媒体检查，并观看代表帧与过渡，分别记录实际完成、近似和未完成内容。

目录中的 `description`、`phases`、`source_peak` 可能引用旧双人执行器标注。例如 Mma Kick 中的平滑和命中修正描述属于旧执行器。通用 `agent_motion.sample_motion` 只做已支持骨架的姿态采样/重定向、时间插值和可选根运动分离；不会自动复用旧双人执行器的姿态滤波、脚部支撑、接触控制或命中反应。旧 `MotionSources` 本身也负责源运动加载与转换，支撑和接触来自相应场景控制器。库素材可应用、某次源采样通过、循环标注存在，都不能直接转成新场景自然度或物理质量通过。

### 主运动：素材优先与连续过渡

默认让合适的动作素材承担全身主运动，保留肩胯发力、重心、支撑脚和节奏。已有连拳等连续运动时优先保留整段，不把每招都重做为程序化 IK。确实缺失的动作再生成，IK主要修正局部接触和支撑；接触数值通过不能替代自然度审查。

通过 MCP 普通 import `agent_motion_sequence.library_sequence_events`，由 Hermes 从自然语言选择实际素材并传入 `segments`；每段包含 `motion_id`、可选秒制 `source_window`、可选 `time_scale`。默认保持原速，根据实际源时长安排场景帧与相邻片的真实重叠，返回普通 `plan.events` 和紧凑时序摘要。按实际结果设置场景帧范围，登记事件并协调 commit；不为填满时长把短拳拉慢，也不把结束姿态冻结称为交叉过渡。

串联时先选朝向、手位、重心及支撑相位相近的起收窗口，保留实际收势，去掉无关中立帧。姿态和根位置、朝向、缩放使用相同过渡权重，重叠时前后素材都继续采样运动。长淡化无法弥补严重不匹配；原速、边界脚步与真实预览仍须检查。全身素材完成后再叠加短窗口接触修正，偏差大时先调站位、时序或素材，不强行把完整运动扭向远处目标。

### 缺失动作与接触补充工具

通过 MCP `execute_code` 普通导入 `agent_interactions`。缺少合适素材时，`guard_events` 可建立护头和基本握拳，`hand_strike_events` 编译准备、命中与收招，`recoil_events` 生成接触后的头躯干反应，`support_step_events` 提供交替支撑脚与根路径。工具只返回 `plan.events`，Hermes 仍负责根据原提示词确定人物、目标、时序与强度，逐个登记后协调 `motion_commit`，用 `verify_interaction` 复查实际接触和支撑；这些工具不应成为有合适素材时的默认全身运动来源。

### 前踢、地面动作与持续接触

这些工具通过 MCP 普通 import 使用，只返回原人物上的开放事件，不创建另一套场景。先完成并 commit 基础姿态/根运动，编译后用 `register_interaction` 登记，再协调 `motion_commit`。基础动作修改后重新编译有关接触，检查实际渲染与保存重载结果。

| 模块与函数 | 用法与范围 |
| --- | --- |
| `agent_leg_interactions.leg_strike_events` | 传入真实目标绑定、起始/命中/结束帧及 `foot`，生成站稳后的抬膝、前踢、收腿与落地，另一脚支撑。目标过远先接近；攻击脚旧支撑先释放。持续行走/移动支撑另行编排，不代表任意踢法。 |
| `agent_contact_interactions.contact_events` | 传入真实目标绑定及 `start_frame < contact_frame <= release_frame < end_frame`，`chain`选择真实手脚，`kind`保留开放动作意图。保持当前链的基础动画，平滑接触、跟随与释放；多人/双手可绑定同一物体不同握点。人物脚步、根路径及物品轨迹分别编排，不在此工具中硬编码搬椅子等完整场景。 |
| `agent_ground_motion.ground_motion_events` | 传入本地 FBX、秒制 `source_window` 和场景帧窗口，把单人运动先验按实际 rest 空间映射到原 Beta。已验证 Rokoko 52/53 骨源，包括 Hips 在 Armature 对象的情况；原 65 骨 direct sampler 不因此变为兼容。`blend_in_frames`从实际基础姿态过渡，`supports`指定实际承重窗口，起身及时松手；末尾留 `settle_frames`，需要站起时设 `expect_standing=True`。 |
| `agent_ground_motion.check_ground_motion` | 测量已登记事件的实际全身皮肤对地、支撑及可选末尾站姿；可指定 `frame_start/frame_end`。`motion_check`和后台重载探针也默认复查。它不认证全身体积无穿插、动态平衡或任意方向击倒。 |
